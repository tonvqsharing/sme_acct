# ADR-001: Database Naming Convention and Primary Key Strategy

## Status
Accepted

## Context
We need a consistent naming convention for PostgreSQL database objects and a primary key strategy for the SME Accounting foundation entities. The platform is PostgreSQL 16.14 with EF Core 9.0.0 and Npgsql 9.0.0.

Two open questions from research validation:
- OQ-1: Naming convention — snake_case (PostgreSQL idiomatic) vs PascalCase (C# native)
- PK Strategy: UUID vs bigint identity vs hybrid

## Decision
1. **Database naming**: snake_case for all tables, columns, indexes, foreign keys, and constraints.
   - C# entity/property names remain PascalCase.
   - Conversion applied via custom `ApplySnakeCaseNamingConvention` in `SmeAccountingDbContext.OnModelCreating`.
   - Example: `Company.CreatedAtUtc` → `created_at_utc`, `AuditLogEntry` table → `audit_log_entries`.

2. **Primary keys**: `bigint GENERATED BY DEFAULT AS IDENTITY` (PostgreSQL 10+ identity columns).
   - `BaseEntity.Id` changed from `Guid` to `long`.
   - `ICompanyScoped.CompanyId` and all FKs (`Branch.CompanyId`, `Account.CompanyId`, `Account.ParentId`) are `long`.
   - Identity sequence reset after seed via `SETVAL(pg_get_serial_sequence(...))` in migration.

## Consequences
### Positive
- Aligns with PostgreSQL community conventions; avoids quoting identifiers.
- `bigint` identity is smaller (8 bytes) and faster for joins/indexes than UUID (16 bytes).
- Sequential values improve B-tree insertion performance and reduce page splits.
- EF Core `ValueGeneratedOnAdd` + `Npgsql:ValueGenerationStrategy.IdentityByDefaultColumn` works natively.

### Negative
- Not globally unique across databases (irrelevant for single-tenant SaaS).
- Requires manual conversion layer (implemented); Npgsql's built-in `UseSnakeCaseNamingConvention` not available in 9.0.0.

### Migration impact
- Existing migration `InitialFoundationSnake` regenerated as `InitialFoundationSeed` with snake_case DDL and seed data.
- Idempotent SQL script `artifacts/sql/InitialFoundationSeed.idempotent.sql` is the deploy artifact.

## Implementation Notes
- `ApplySnakeCaseNamingConvention` iterates all entity types, properties, and FKs; applies PascalCase → snake_case via simple character scan.
- `BaseEntity.Id` setter made public to allow EF Core `HasData` seed.
- Seed data: `Company` (Id=1, Code=DEMO), `Branch` (Id=1, CompanyId=1, Code=HO).
